## Pontos corretos

- Separação limpa entre camada pura (`montar-documento.ts`, `gate-exportacao.ts`) e efeitos impuros (`tela-exportacao.tsx`), com `aoBaixarArquivo`/`obterDataDeHoje` injetáveis — mesmo padrão já usado no restante do projeto.
- O isolamento do bookkeeping de data (RN-011) do "erro estrutural real" via `DATA_PLACEHOLDER_CHECAGEM` é uma solução elegante para o problema de "documento sem data ainda, mas por motivo válido" vs. "documento estruturalmente incompleto" — e o placeholder é comprovadamente descartado antes da exportação real (não há caminho de código que o propague ao JSON final).
- `TelaRevisao` é puramente apresentacional (não recomputa pendências, não persiste) — consistente com NEG-004.
- Verifiquei que vários bloqueantes de §11 (horários fora de ordem, violação dos 350 m, violação de tipificação) são estruturalmente **impedidos na origem** pelas etapas de edição, e por isso nunca ocorrem como estado vivo: `editarHorarioPassante` recusa e não confirma o offset fora de ordem (`src/formulario/viagens/acoes-grade.ts:71-90`); `inserirEmSecao`/`fluxos-secao.ts:202,250` recusam a inserção que violaria os 350 m; a criação de Serviço já filtra o dropdown de característica pelo tipo (comentário `src/formulario/servicos/servicos.tsx:35`, confirmado pelo E2E `servicos.spec.ts:28`, "dropdown filtrado pelo tipo"). - "Seções ou Locais incompletos (sem nome, sem geolocalização, município não derivável)" **é** coberto — não pelo `coletarPendencias`, mas pelo braço de validação estrutural do gate (`validarParaExportacao` → `esquemaDocumentoOperacao.safeParse`): `nome`/`municipio` são `min(1)` obrigatórios e `Local` exige ao menos uma geolocalização via `superRefine` (`src/shared/contrato/esquema.ts:96-120`).
