## Problemas encontrados

1. **(Baixa — dead code + imprecisão em documento vinculante)** `hover:shadow-sombra-2` em `CLASSES_INTERATIVO` ([`painel.tsx:77`](../../src/shared/ui/painel.tsx#L77)) é **no-op no único uso existente**: com `elevacao="padrao"` (default dos dois cartões) o painel já emite `shadow-sombra-2` em repouso ([`painel.tsx:71`](../../src/shared/ui/painel.tsx#L71)), então a sombra no hover é idêntica à de repouso. O feedback de hover que de fato existe — e que **atende** o critério, pois a task pede literalmente "fundo acinzentado" — vem só do `hover:bg-cinza-50`. Duas consequências:
   - O JSDoc afirma "`sombra-2`→**hover mais forte**" ([`painel.tsx:52`](../../src/shared/ui/painel.tsx#L52)) — **factualmente falso**; não há sombra mais forte (e não poderia haver: `sombra-3` é reservada a flutuantes, doc 18 §2/§5).
   - O doc 18 §3, **vinculante**, herdou a imprecisão: "hover (`sombra-2` + `cinza-50`)" ([`18-DESIGN_SYSTEM.md:57`](../18-DESIGN_SYSTEM.md#L57)) sugere que `sombra-2` é efeito de hover.
   - O teste `expect(classes).toContain("hover:shadow-sombra-2")` ([`painel.test.tsx:144`](../../testes/unitarios/shared-ui/painel.test.tsx#L144)) **trava o dead code no lugar**, dando falsa sensação de cobertura.

O foco gerenciado foi implementado via `useEffect` ([`tela-inicial.tsx:77-81`](../../src/formulario/tela-inicial/tela-inicial.tsx#L77-L81)) e o `Esc` ([`tela-inicial.tsx:210-214`](../../src/formulario/tela-inicial/tela-inicial.tsx#L210-L214)), mas **nenhum dos dois tem teste** — nem unitário nem E2E. Na leitura literal, o **cartão** seria focável; na entrega, quem é focável é o **controle interno** (input `sr-only` / `Botao`), com o cartão exibindo o anel via `focus-within`.
