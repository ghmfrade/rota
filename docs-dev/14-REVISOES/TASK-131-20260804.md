## Problemas encontrados

1. **(Baixa — dado sintético) `distanciaM: waypoint.distance ?? 0`
   (`src/formulario/roteamento/nearest-osrm.ts:101`) inventa um valor quando o OSRM omite
   `distance`.** Zero metro significa, em qualquer leitura razoável, "a coordenada está
   exatamente sobre a via" — a leitura mais forte possível, produzida justamente no caso em
   que não há informação nenhuma. É o oposto do critério que a task aplica ao `name`
   ("nunca um nome inventado") e roça o princípio 2 do `docs-dev/04` (não inventar o que a
   spec não diz). Impacto **hoje é nulo** — não há consumidor de `distanciaM` —, mas a
   TASK-133 é o consumidor natural e um limiar do tipo "só sugerir se a via estiver a menos
   de N metros" leria esse `0` como o melhor caso possível.
   *Correção sugerida:* tratar `distance` ausente/não-finito como `semResposta`, ou tornar
   `distanciaM` opcional no ramo `ok: true`. Qualquer das duas exige um teste do caso.
2. **(Baixa — lacuna de teste) Nenhum teste cobre `distance` ausente ou não numérico.** Todos
   os casos válidos passam `distance` explícito (`nearest-osrm.test.ts:95-126`). O
   comportamento do item 1 não está fixado por teste, então uma mudança futura nele não
   quebraria nada.
3. **(Informativa — não é defeito) O timeout depende de o `fetchFn` honrar `signal`.** Um
   `fetchFn` injetado que ignore o `AbortController` faria a promessa nunca resolver. Vale
   para o `fetch` global (que honra) e para o mock do teste (que honra explicitamente); só
   registro porque a injeção é pública via `OpcoesNearestOsrm`.

Nenhum problema de severidade Média ou Alta. Nenhuma violação de RN de criticidade Alta e
nenhuma violação de NEG-xxx.
