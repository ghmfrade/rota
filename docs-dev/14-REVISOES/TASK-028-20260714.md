## Problemas encontrados

(ordenados por severidade)

1. **[Baixa — qualidade] Input muda de não-controlado para controlado.** No E2E o React emite `A component is changing an uncontrolled input to be controlled`. Causa: a célula "criável" ([etapa-viagens.tsx:209-213](../../src/formulario/viagens/etapa-viagens.tsx#L209-L213)) usa `<input type="time">` sem `value`; ao criar a Viagem, a mesma posição de DOM passa a ser a célula de partida com `value` ([etapa-viagens.tsx:188-194](../../src/formulario/viagens/etapa-viagens.tsx#L188-L194)). Funciona (4 E2E verdes) e não viola RN, mas é antipadrão React. Sugestão: `value=""` na célula criável ou `key` distinta para forçar remontagem. **Não bloqueante.**

## Violações de escopo

- Nenhuma que ultrapasse RN Alta ou NEG-xxx. **Ponto de atenção declarado:** `atualizarHorarioSaida` ([acoes-grade.ts:41-53](../../src/formulario/viagens/acoes-grade.ts#L41-L53)) permite reeditar a partida de uma Viagem **já existente** — comportamento não nomeado literalmente na Spec 04 §8.2, marcado no código como *inferência controlada da Análise da Task*. Verificação independente contra a spec: a 1ª Seção nunca é passante (offset sempre `00:00:00`, RN-063), logo reeditá-la não colide com a regra de passante→âncora (§8.2, TASK-029); como a 028 não introduz âncoras, re-derivar todos os offsets pela sugestão inicial produz resultado idêntico a apenas trocar `horario_saida`. Aceitável e coerente. **Ver Pendências.**
